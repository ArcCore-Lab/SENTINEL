# SENTINEL 竞赛 MVP 需求

日期：2026-10-09。需求来源为本次对话和[开发计划书](../pdplan.md)。本文件将计划书的完整目标收敛为截止前可验收范围；赛事细节以 官方核查（见赛事提交包） 为准。

当前先决门槛状态：**真实赛事 Agnes 模型已通过 AGH→固定 MCP→本地 Foundry 闭环；已知 ShareVault 夹具的 M1–M6 在明确反馈纠错后形成报告。** 自主发现与泛化能力未验收。

## 目标和用户

独立开发者在 2026-10-15 12:00 前交付可提交作品。演示对象为本地授权 Solidity 合约。输入为合约、明确的目标性质和测试环境；输出为可复现的状态转移假设、测试执行结果和证据路径。

## P0：先决门槛

1. 使用官方 AGH，遵守赛事流程和 Agnes 模型限制。
2. AGH 经官方支持的插件或 MCP 接口调用受限的本地 Foundry。
3. 一条简单 Solidity 测试真实通过，保存 AGH、工具、Foundry 三层日志。
4. 若无模型 Key，仅可把官方模拟模式结论标为工具链验证；真实模型调用仍为未验收。

工具链闭环已通过。模拟 provider 只用于本机工具链测试，不证明状态推理或漏洞发现能力；真实 ShareVault 首轮推理错误，说明报告仍需状态核对。

## P0：门槛通过后的最小作品

1. 针对一个**授权、离线、固定**的逻辑漏洞样例，完成计划书 M1–M6 的最小链条：识别关键函数与状态变量；写出初始状态、操作序列、状态变化和不变量；提出具体漏洞假设；选择预审 Foundry 测试并执行；根据结果修正或否定假设；输出证据报告。
2. AGH 实际调度上述流程，留下至少三个连续且可辨识的步骤及模型、工具调用记录。不能将预先写好的分析结果包装成 AGH 输出。
3. 报告关联每个假设与测试标识、测试断言、编译结果、测试退出码、业务不变量判断及证据路径。**测试通过不自动等于漏洞成立**；无证据时标为待验证。
4. 提供正常、边界、失败三类本地样例及一次端到端复跑；三类固定样例均已有真实 Agnes 经 AGH→MCP→Foundry 的证据。刻意失败样例精确分类为 `expected_fixture_test_failure_no_finding`，真实模型解释为无漏洞发现；见技术验收记录（见赛事提交包）。
5. 使用 AGH 原生工作台展示，演示录像与日志一致；不另建前端。

当前固定样例为本地人工标注的 ShareVault 份额记账错误，状态序列、业务不变量、测试标识和实际工具结果见样例说明（见赛事提交包）。真实 Agnes 分析、工具执行与纠错已发生；最终报告（见赛事提交包）为人工复核摘要，不是独立发现。M6 文件名与内容以决策 D-014（见赛事提交包）为准。

## P1 / P2 / 未来

- P1：扩展至计划书 M1 的三份合约、M3 的三类漏洞；在审查和沙箱机制实测后研究测试生成及最多两轮修复。
- P2：补齐计划书提出的完整 JSON 文件集、批量样例和报告体验；只在 P0 稳定且不影响截止时间时做。
- 未来：科研基线与数据集、SRCA Web3 接口、多人/在线任务和生产部署。均不计入本次门槛。

## 非功能验收

- 运行目录固定在仓库内的样例目录；工具只执行预先审查的 Foundry 测试入口，限制时间、资源和网络；关闭 FFI。模型可以提出测试意图，不能提供待执行的 Shell 命令或未经审查的源码。
- 密钥只由运行环境注入，不进仓库或日志；日志对秘密值脱敏。
- 任何指标只来自可复查的运行记录；测试失败、模拟模型和未运行项目均明确标注。
- 单人可按文档重现；新增依赖和组件须有截止前的必要性。
