# 后续科研实验计划

本文件是研究设计，尚无漏洞发现结果或性能指标。竞赛提交前只保留能复用的输入、执行轨迹和证据结构，不以研究扩展挤占 MVP 时间。

## 最小可证伪问题

在固定授权合约、可见源码、工具预算和相同模型条件下，显式写出状态变量、操作前置条件与转移序列，是否比不采用该结构的同模型基线更容易产生**经本地测试证实**的逻辑漏洞假设？

这对应[开发计划书](../pdplan.md)的 RQ1。RQ2（执行反馈是否提高效率）和 RQ3（状态引导测试是否节省预算）在论文阶段另行验证，竞赛样例不支持这些结论。

## 实验边界

- 数据：自建且授权的离线合约样例；先给每例标注漏洞条件和可验证测试。后续公开数据集要核查许可证和标签质量。
- 对照：相同 Agnes 模型、提示预算、工具入口、运行次数和固定种子/温度条件；只改变状态转移结构。另列纯规则或静态分析基线，避免混淆。
- 完整实验可按计划书的 2×2 设计比较「有/无状态表示」与「有/无执行反馈」，一次只归因一个因素；四组都必须拥有相同数据、模型和预算。
- 指标：经测试验证的真阳性、误报、完成率、调用/工具开销与时间；报告每例原始结果和失败原因。
- 分析：保留失败案例、重复运行波动和人工标注分歧。单个竞赛样例不能支持泛化或新颖性主张。

## 验收顺序

AGH→Foundry 工具链已由真实赛事 Agnes 模型和本地模拟 provider 分别验证；ShareVault 人工状态序列与不变量见样例说明（见赛事提交包），真实模型首轮错误与明确纠错见报告（见赛事提交包）。这一例暴露了状态推理可能失真，属于研发观察，不构成 RQ1 的比较结果、漏洞发现率或模型泛化结论。提交后若开展对照实验，任何科研结论均须回溯到模型请求、AGH 轨迹、Foundry 测试和人工复核。
